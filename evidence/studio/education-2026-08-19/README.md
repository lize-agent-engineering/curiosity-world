# 教育主线真实模型验证（2026-08-19）

## 怎么跑的

`pnpm spike:studio:real`，直接驱动教育管线（管线不依赖存储），并发 2，单次调用超时 600s，
coder / planner / reviewer 都是 `openrouter:z-ai/glm-5.2`。

样本是 6 个真实儿童问题，跨领域（相对运动、生物、化学、光影、气象、流体），年龄铺开 5–11 岁；
每个跑「创建 → 家长真会提的追加要求」两步。产物 HTML 全部在 `pages/`。

这一轮把样本矩阵整个换掉了：之前的 spike 验的是通用模式的应用需求（番茄钟、贪吃蛇、记账看板），
而通用模式已经不是产品主线，等于**证据和产品是两回事**。

## 旁白：最大的未知数已经证实

旁白是这一轮之前才加的能力，模型会不会遵守 `curiositySay` 契约完全没验过。结果是 **6/6 都遵守了**，
而且保底实现一字不差地抄了，所以下载带走的页面照样能读。

台词质量也对：

> 「你觉得，月亮会怎样？选一个答案。」→「好，再走一次，看月亮到底怎样。」

先猜后揭示，正是提示词要求的顺序，不是把答案念出来。

顺带修掉了**指标本身的一个 bug**：`caterpillar` 页面把 `curiositySay` 包了一层本地 `say()` 再到处调，
原来的正则只数直接调用点，会把它误判成"不会说话"。指标要问的是"模型接受契约了吗"，不是"call site 怎么拼写"。

## 编辑块失配：查清了，并且改了

2 次回退成整页重写，失败码都是 `EDIT_BLOCK_NOT_FOUND` —— 模型**输出了编辑块，但 SEARCH 段对不上原文**。
这不是"改动太大所以本来就该重写"，是真的匹配问题。

据此改了降级链：**失配后先带着应用器自己的错误指引重试一次定点编辑，两次都不中才回退整页重写**。
应用器本来就把失败写成了模型可执行的指引（"请重新从当前 HTML 里逐字复制…"），之前当死代码删掉了，
现在有数据支撑，加了回来并补了测试。重写一份 20KB 的页面比重试一次贵得多，而且会丢掉
"无关区域一字不动"的保证。

这个改动**在本次矩阵之后**，所以上面 67% 的命中率不包含它的效果。

## 延迟：没过，不粉饰

单次创建 p95 483s（8 分钟），门槛 240s，**没过**。而且这次不能全赖并发——最快的一个也要 269s。

原因是教育页面本身比通用应用重：18–23KB，要画场景图形、要旁白、要预测环节、要迁移挑战、
要给家长看的小结。240s 这个目标是对着通用模式的产物定的（中位 21KB 但结构简单得多）。

**没有调门槛来让它变绿。** 记在这里，并且：

- 产品上已经做的缓解：三阶段命名进度 + 代码一行行流式写出，让等待可读，而不是转圈；
- 真正的解法是把长文档按区块并行生成再拼装，列在提交文档的扩展优先级第 5 条。

结论：**质量四项全过，延迟一项未过。** 产品可交付，性能是已知短板。
